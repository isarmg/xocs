# 数据结构

接口索引：[collections](catalog.md#collections)、[memory](catalog.md#memory)、[math](catalog.md#math)、[lookup](catalog.md#lookup)。

## 集合与内存

`collections` 按消费者区分通用哈希表、数据库哈希表、顺序表、缓存、位集合、槽位、内联字符串和内联向量。同一种上游算法有多个用途所有者时，类型身份与编译边界保持明确；使用方通过当前路径依赖选择对应包。

`memory` 提供 arena、索引 arena、分配器、字节布局、输出引用、借用包装及引用转换。集合的元素移动、地址稳定性、并发访问和释放时点属于 API 合同，不能仅根据内部存储形式推断 `Send` 或 `Sync`。

并发槽位表保留跨线程持有、移除和释放的同步；调用者需要让 guard 的生命周期覆盖实际访问。arena 中分配对象的销毁规则与普通 `Box` 不同，具体见对应分配器和容器的 Rust 文档。

## 数值、随机与静态表

`math` 提供数值 trait、类型级整数、固定数组、大整数、指纹以及不同用途的伪随机生成器。查找表生成用的随机数与密码随机数分开：认证与密码使用[密码学熵源](cryptography.md)，不能替换为快速 PRNG。

`lookup` 按 JS 与 CSS 管线分别组织静态查找、散列算法、生成器和过程宏。编译期生成与运行时查询使用匹配的数据格式；生成器包属于构建宿主，生成的表属于其消费者目标。
