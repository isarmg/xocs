# Linux AMD64 专用化与实现优化

本轮以 `75b525a5ab399e67489e0618e16a31d6ffc0d49c` 为冻结基线，支持范围收敛为 AMD64 Linux GNU/glibc 原生服务与构建宿主，浏览器继续使用 WASM。业务逻辑全部由 Rust 承担；手写生产 JavaScript 只保留加载和启动失败回退，具体边界见[架构说明](maintained-design.md)。

## 实现变化

| 范围 | 结果 |
| --- | --- |
| 平台契约 | 项目入口直接执行 Cargo 也检查 HOST/TARGET；拒绝 ARM、GNU x32、musl 和非 Linux 宿主，保留浏览器 WASM 与原生测试 |
| 系统层 | Linux ABI、libc、raw syscall、epoll/eventfd、熵源和停车层只保留受支持实现；C 头对照测试检查关键布局 |
| SQLite | 固定仓库 C 源码构建；删除 SQLCipher、外部库发现和多数据库支撑，保留实际编译选项、Tokio 池、事务和类型编解码 |
| 线程安全 | 删除 SQLite 行错误的 `Sync` 声明；行仍可跨线程移动，Debug 对副本解码以保护已有借用 |
| 会话维护 | 有界键集游标越过活跃前缀，删除时重验期限；共享游标处理并发、删行、复用和回绕 |
| 连接同步 | SQLite worker 复用 Tokio 公平锁，明确保证入队先于交接；回归覆盖取消和调度预算耗尽 |
| DOM | 视图协议收缩为 CSR，删除 SSR、流、水合、模板及无消费者的转义实现；修复属性微任务重入后丢失调度 |
| HTTP | 开发代理复用 HTTP/1 连接池，保持上传/下载总期限、流、Cookie/CSRF 和重复响应头；删除未消费通用客户端与中间件 |
| 媒体 | 静态服务共享不可变基路径，消除服务克隆中的路径分配；校验 URL 路径穿越、反斜杠和 NUL |
| 资产构建 | 独立 JS/CSS 管线拆包；单个输入快照复用工作区解析和内容摘要，跨快照仍重新读取 |
| 当前接口 | 删除废弃构造器与别名、MaybeSignal、SQLite 空特性和旧查询包装；WASM 初始化仅接受当前对象参数 |
| 同步与容器 | 通知回调、tag 和 Waker clone/drop 抛出 panic 后仍维持链表、计数和注册状态；并发槽位通过真实线程验证延迟释放与旧键失效 |
| 加密与熵源 | 密码随机源统一使用 system-entropy；修正 SHA-512 软件后端选择串扰与强制 AVX2 参数签名，标准向量覆盖默认、软件及 AVX2 路径 |
| 编译器安全 | 安全 Pattern 接口的自定义字节位置改用检查切片，拒绝越界、倒序和非 UTF-8 边界；明确 unsafe 边界与生命周期 |
| 依赖深度裁剪 | 清理未声明特性、旧 Rust 探测、HTTP C FFI、二进制记录嵌入式适配器、未消费数据库钩子和 JSON schema 集成；保留实际 Linux/WASM 消费路径 |
| 视图职责 | DomView 独立于可选属性追加能力，删除无消费者的类型擦除属性层；验证纯渲染视图的状态复用与单次释放 |
| 本地时区 | POSIX 规则按候选 UTC 反查，修正重复时刻排序；TZif 使用准确的 gap/fold 半开边界，同偏移名称切换不再误报歧义 |
| 维护文档 | 当前架构、支持范围和开发步骤集中说明；精确来源数量由管理器生成，旧审查保留为历史证据 |

## 可核对的结构变化

维护包从 240 个变为 229 个：退役 12 个无剩余消费者的包，新增独立 CSS 编译器包。当前为 220 个基础包和 9 个项目包，根锁完整图同为 229 个包。额外删除 DOM 内的两个无消费者实现来源；活动原始身份从 348 个变为 334 个，累计退役 63 个。397 份原始发布归档、许可材料和既有迁移记录全部保留。

退役包为 `terminal-probe`、`compiler-entropy`、`http-client`、`ip-addresses`、`intrusive-futures`、`windows-compiler`、`windows-library-discovery`、`system-library-discovery`、`random-seed`、`portable-stream`、`record-stream`、`compiler-probe`。DOM 退役来源为 `const_str_slice_concat@0.1.0` 和 `html-escape@0.2.15`。JS/CSS 的来源重新分配给真实所有者，不重复制造来源或借删除代码抹去历史。

这些数字用于清点。源码删减、包数和不再支持的 API 均不能代替运行性能或正确性证据。

`src/` 中的文件从 12,522 个、190,366,431 字节降至 10,008 个、150,756,400 字节，减少约 20.8%。这里包含源码、保留测试、文档和许可，CSS 文件移动按最终实际文件计数；不包含原始归档或构建产物。[计量口径与原始数字](measurements/source-tree.json)可用于核对，不能解释为程序运行内存下降。

## 测量

[编译器拆分测量](measurements/compiler-split.md)给出冻结输入、复现脚本、原始 JSON 和限制。数据来自拆分阶段的冻结样本；本轮后续清理未重新测量这组编译时间：

| 场景 | 基线 | 拆分后 |
| --- | ---: | ---: |
| 编译器及依赖的空 target 构建 | 61.973 s | 42.820 s |
| 仅 CSS 源码变更后的重编译 | 31.459 s | 14.223 s |
| 仅 JS 源码变更后的重编译 | 31.155 s | 17.026 s |
| 单个源码快照耗时中位数，独立实验、各 6 次 | 13.846737 s | 7.980404 s |

冷编译的单进程 RSS 峰值下降，但并行进程树的 RSS 峰值从 2.441 GiB 增至 2.569 GiB，约增加 5.2%。每个编译场景只有一次观测，快照实验也没有随机交替；这些数据支持本环境中的实现取舍，不是整产品加速比例或硬件无关保证。

[媒体路径克隆实验](measurements/media-path-clone.md)中，100,000 次克隆从 100,000 次分配降为 0；这个结论只针对服务基路径克隆，没有据此推算 HTTP 吞吐或请求延迟。

最终浏览器 WASM 从 3,286,591 字节降至 3,264,287 字节，减少约 0.68%；同一 Python gzip9 口径从 1,004,177 字节降至 998,303 字节，减少约 0.58%。[实际产物摘要与源文件计量](measurements/browser-wasm.json)保留前后 SHA-256。此比较包含本轮全部改动，不是只隔离 DOM 重构的实验；gzip9 计量也不等于发布流程生成的 `.gz` 大小。

## 验收范围

本轮按原生业务、系统后端、构建器、浏览器与来源记录分别验证。命令入口见[开发文档](development.md)和 `scripts/test-maintained.sh`。构建成功或来源核验不能替代真实业务验收，原有忽略测试也不能计作通过。

已执行的验收包括：

- 原生业务、安装工具、数据库绑定和会话清理测试；SQLite 多语句行映射、错误传播、锁交接与协作预算耗尽均有针对性回归。日期回归还覆盖七组隔离时区规则和精确转换边界。测试输出中的 4 个原生 ignored 项是由父测试显式启动的隔离子进程入口，不重复计数。
- 资产构建器 57 项测试及 4 项配置格式契约；生成的初始化 JS/WASM 在 Node 中真实执行，覆盖对象参数、默认 URL、启动次数、流式加载回退和旧调用形式拒绝。
- CSR/浏览器的 70 项原生单元与集成测试、438 项文档测试（另有 13 项浏览器域测试）；现有 4 项文档忽略测试未计为通过。
- `scripts/test-maintained.sh` 的 382 项基础实现与消费者测试，覆盖 ABI 布局、系统熵、epoll、日期、SQLite、DOM、通知 panic 恢复、并发槽位、密码随机数、SHA 标准向量与二进制记录等。该数量与前述分组存在重叠，不相加形成总数。
- SHA-512 另以强制软件与强制 AVX2 配置执行标准向量测试，各 2 项通过；AVX2 在支持该指令集的本机执行。向量结果不单独证明具体调度分支被选中。
- 来源管理器 40 项、独立性与平台检查 22 项、审计工具 9 项测试；229 包来源核验与 Linux/WASM 空 Cargo home 离线解析通过。
- 项目格式检查、三组项目 Clippy `-D warnings`、离线服务构建、生产 WASM 构建和资产契约检查通过。实际原生与 WASM 消费图的检查已清理编译告警；独立 native-calendar 测试入口仍有两个未使用辅助函数告警，不将项目检查扩大为所有继承测试和特性组合均无告警。
- Chromium 和 Firefox 均通过 CI 清单所列的全部 14 组浏览器场景：双语、后台布局、账户设置、后台清理、内容管理、接口契约、界面运行时、异步状态、网络生命周期、启动失败、Rust 域规则、公开页脚、公开布局和匿名评论。测试执行最终真实 WASM，并核对资源摘要与来源收据。
- 最终服务二进制通过 `scripts/smoke.sh`：真实 HTTP 登录与权限、内容增删改、文件选择器上传和引用删除冲突、SQLite 重启持久化，以及两种浏览器的真实后台操作均通过；同时验证 WASM MIME、gzip、ETag、HEAD 和 304 响应。

本轮未测量端到端吞吐、请求延迟或完整服务内存，也未验证所有上游库原始 API 组合。仓库源码已针对当前产品收缩；后续发现的真实热点应继续以消费者和可复现证据改进。
