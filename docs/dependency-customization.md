# 依赖分析与深度定制

维护目标是博客实际行为、资源开销和清晰的代码责任。依赖可以合并或拆分；包数只用于清点，不能替代正确性验证或性能测量。当前结构见[架构说明](maintained-design.md)，精确包数与来源见[生成清单](THIRD_PARTY_RUST_SOURCES.md)。

## 设计依据

先从服务端、浏览器、构建工具和测试入口检查消费者、特性、公开类型、宏展开及构建输入，再决定保留范围。普通运行库、过程宏、宿主构建脚本和 WASM 输出有不同的执行边界；合并不能制造依赖环或破坏类型身份。

同一协议只保留必要实现，例如 HTTP Body、序列化 trait、哈希接口、Future 和锁接口。独立的大编译阶段则应保留合理编译粒度：一个大包修改任一文件会整体失效，包数减少并不自然带来更快构建。

## 当前定制

| 范围 | 实现决定 | 验证重点 |
| --- | --- | --- |
| Linux 系统层 | 固定 AMD64 Linux ABI、原始系统调用和 epoll/eventfd 后端；移除其他架构源码及发现逻辑 | I/O 就绪、取消、唤醒、随机数短读与中断、平台拒绝 |
| SQLite 原生构建 | 固定内置 SQLite，保留产品编译选项和数值限制 | 绑定、线程模式、参数限制及实际 SQL |
| SQLite 访问层 | 保留 SQLite + Tokio 池及事务，移除其他数据库和离线查询分析支撑 | 行借用/移动、事务、取消、忙等待、FromRow 和真实持久化 |
| 会话清理 | 共享有界键集游标逐批推进；到尾部后回绕 | 活跃前缀不能饿死过期后缀，并发、删行和 rowid 边界 |
| DOM | 视图与属性协议收缩为 CSR；删除 HTML 流、水合和模板构建 | 更新、动态列表、事件、Portal、卸载与浏览器状态 |
| 开发代理 | 直接复用 Hyper HTTP/1 连接池，删除独立通用客户端 | 请求体/响应体流、背压、取消、完整 deadline、Cookie/CSRF、重定向和 hop-by-hop 头 |
| JS/CSS 编译器 | 按相互独立的两条编译管线拆包，工具直接调用 | JS/CSS 语义、相同输入的输出、冷构建和单管线修改后的编译成本 |
| 源码输入收集 | 单快照复用工作区解析与文件摘要 | 输入变化检测、来源完整性及构建器过期判断 |
| 并发基础层 | 通知链表按提交状态、计数更新、用户回调顺序处理，panic 后仍可使用；并发槽位保留真实 std 同步 | Waker 的 wake/clone/drop、tag panic；跨线程持有、移除与释放 |
| 密码随机数与哈希 | 合并系统熵实现，保留完整错误；修正 SHA-512 独立后端选择和 AVX2 压缩器签名 | SHA-256/512 标准向量、padding、分块、百万 a；默认、软件和 AVX2 |
| 编译器安全接口 | 对安全 Pattern 返回的位置使用检查切片 | 自定义越界、倒序、非 UTF-8 边界和借用路径 |
| 配置解析 | 移除无法启用的终端调试实现和唯一的终端探测依赖 | UTF-8 错误位置、CRLF、无效语法和日期合同 |

各改动保留原始归档和许可证。删除能力以完整消费者核查为依据；部分来源仍有保留代码时，不能将整个来源标记退役。

## 验证和测量

系统层与 SQLite 的 unsafe 边界需要按实际调用链审查。SQLite 的值转换会修改内部状态，行内部还包含非同步 `OnceCell`；因此行只允许移动，移除了错误的 `Sync` 声明，并加入编译期回归约束。

构建收益采用冻结源码、相同工具链、相同配置和独立输出目录对比；同时记录单进程及进程树总内存，不能只挑有利指标。性能数字及完整验收结果记录在[本轮优化报告](optimization-linux-amd64.md)。早前的具体错误修复和当时测试记录保留在[内建依赖实现审查](dependency-review.md)，不能代替当前版本的验证。

原生单元测试、WASM 编译、真实浏览器、HTTP/CSRF、持久化、安装与维护分别验收。来源工具验证本地输入闭包和历史记录，不证明语义等价；构建速度、制品体积、运行内存和请求延迟也分别评价。
